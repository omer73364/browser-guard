BROWSER GUARD / 1.0

A few methods.
Clear boundaries.

Start with whole-page controls. Add scoped areas and exceptions when you need them.

Getting started

Install the published package in your application:

npm install browser-guard

Then import the package in your browser application or framework:

import Guard from 'browser-guard';

Guard.enable({
  copy: true,
  select: true,
  rightClick: true,
  savePage: true,
  print: true,
  console: false,
  antiDebug: false,
  consoleAction: 'noop',
  onViolation: (type) => console.log('Guard:', type)
});

// Later, pause protection:
// Guard.disable();

Without a bundler

Use the published CDN build with a script tag after your content. The version is pinned so updates do not change your site unexpectedly.

<script src="https://cdn.jsdelivr.net/npm/browser-guard@1.0.0/guard.js"></script>
<script>
  Guard.enable({
    copy: true,
    select: true,
    rightClick: true,
    savePage: true,
    print: true,
    console: false,
    antiDebug: false
  });
  // Later: Guard.disable();
</script>

The ESM build is guard.mjs; the classic script is guard.js. CommonJS consumers can use require('browser-guard'). No runtime dependencies are required. Creating an instance requires a browser document.

Every public method

Use the global Guard methods for one whole-page controller, or the same methods on a controller returned by Guard.create(). Options and event objects are described below.

Guard.create(options?)

Create an independent, inactive controller. Returns a GuardInstance. Pass create options below, or omit them to protect the whole document. Call enable() to activate its saved feature settings.

guard.enable(options?)

Returns Status. With an options object, validates the entire update, saves and applies only the named feature flags; omitted flags keep their current state. With no argument, restores all saved flags. To activate the default controls plus custom changes on a new instance, pass options to create(), then call enable().

guard.disable(features?)

Returns Status. Omit features to pause every feature. Pass one feature name or an array of names to pause only those features. Saved settings and subscriptions are preserved, so enable() can restore them.

guard.status()

Returns a new object containing the current seven active feature booleans and consoleAction. It reports active state, not the saved configuration. It does not change protection.

guard.on('violation', listener)

Subscribe to violations. The only event name is violation. The listener receives one ViolationEvent object. Returns an unsubscribe function; calling it returns true when it removes the subscription and false if already removed. Duplicate subscriptions are independent.

guard.destroy()

Permanently disables this instance, removes handlers, styles and timers, and clears callbacks and subscriptions. Returns undefined. Repeated calls are safe. enable(), disable() and on() then throw; status() remains readable. Create another instance to restart.

guard.lock(options?)

Alias for enable(options). Accepts the same options and returns Status.

guard.unlock(features?)

Alias for disable(features). Accepts a feature name, array, or no argument and returns Status.

guard.unlockAll()

Alias for disable() with no arguments. Pauses every feature and returns Status.

Global methods

Guard.enable(), disable(), status(), on(), lock(), unlock() and unlockAll() use one lazy document-wide controller. Guard.destroy() disposes of that controller and resets it, so a later Guard.enable() creates a fresh one. This differs from an independent destroyed instance, which cannot be reused. Guard.status() before initialization reports all features off. Imports are safe during server rendering; create or enable protection only in a browser lifecycle hook.

Every configuration parameter

All parameters are optional. Feature flags must be booleans. Unknown option names, invalid value types, invalid selectors and missing targets throw before installing protection. The defaults below are the saved defaults for a newly created controller; create() itself leaves all controls inactive.

copy

Type: boolean · Default: true

Cancel copy events within the target, except allowed elements.

select

Type: boolean · Default: true

Discourage selection with scoped CSS and selection-event handling. Exceptions stay selectable.

rightClick

Type: boolean · Default: true

Cancel context-menu events within the target, except allowed elements.

savePage

Type: boolean · Default: true

Intercept Ctrl+S or Command+S when the page receives the shortcut in scope.

print

Type: boolean · Default: true

Hide the target when printing and emit a print event. Does not cancel the browser’s print dialog.

console

Type: boolean · Default: false

Enable a window-size DevTools heuristic and intercept DevTools shortcuts in scope. False positives are possible; detached tools cannot be reliably detected.

antiDebug

Type: boolean · Default: false

Execute a debugger statement every second. An attached debugger can pause even in a separate window. Users can disable pauses; this is not reliable detection.

consoleAction

Type: 'noop' | 'hide' | 'redirect' · Default: 'noop'

Response when the size heuristic triggers: noop only notifies; hide conceals the target until detection ends or is disabled; redirect navigates the whole page to about:blank. Only used with console enabled.

onViolation

Type: function | null · Default: null

Callback (type, event) invoked for each violation. type is the violation name; event is the detailed object below. Set null to remove this callback. Separate on() subscriptions remain registered.

target

Type: CSS selector | Element | Document · Default: document

create() only. Choose the whole document or one existing element from the current document. A selector must match when create() runs. Cannot be changed with enable().

allow

Type: string[] · Default: editing fields + data-guard-allow

create() only. CSS selectors exempt matched elements and their descendants. Replaces the defaults rather than extending them. Defaults: input, textarea, select, [contenteditable]:not([contenteditable="false"]), [data-guard-allow]. Pass [] to remove exceptions. Print and window effects still apply.

A complete independent controller

const guard = Guard.create({
  target: document,
  allow: ['input', 'textarea', 'select', '[data-guard-allow]'],
  copy: true,
  select: true,
  rightClick: true,
  savePage: true,
  print: true,
  console: false,
  antiDebug: false,
  consoleAction: 'noop',
  onViolation: (type, event) => {
    console.log(type, event.feature, event.target);
  }
});

guard.enable(); // Activate the configuration supplied above.
guard.disable('copy'); // Allow copying while other controls remain active.
// Later: guard.disable(); // Pause everything.
// Later: guard.enable();  // Restore saved settings.

02 Configuration

Guard.enable() enables the standard controls for the whole document. For independent lifecycle management, Guard.create() returns an inactive whole-page instance. Calling enable() applies its saved configuration. These are the default feature flags:

FeatureDefaultBehavior
copyOnPrevent clipboard copy events in scope.
selectOnApply owned CSS to discourage text selection.
rightClickOnPrevent the scoped context menu event.
savePageOnIntercept Ctrl/Command + S in scope.
printOnHide the target in print media.
consoleOffCheck window dimensions and intercept scoped DevTools shortcuts.
antiDebugOffRequest a debugger pause every second.

All feature flags must be booleans. Invalid updates throw before changing the configuration. consoleAction accepts 'noop', 'hide', or 'redirect'.

// Only the named feature changes; other active flags stay as they are.
guard.enable({ copy: false });

// Read current active flags and consoleAction.
const status = guard.status();

03 Scope & exceptions

target accepts a selector, an element from the current document, or document. It defaults to the whole document. The target must exist when you create the instance.

Editing fields and elements marked data-guard-allow are exempt by default. A custom allow array replaces these defaults; an empty array removes exceptions.

const guard = Guard.create({
  target: '#article',
  allow: [
    'input', 'textarea', 'select',
    '[contenteditable]:not([contenteditable="false"])',
    '[data-guard-allow]', '.copyable'
  ]
});

Exceptions cover matched elements and their descendants, including content inserted later. They apply to copy, selection, context menus, save shortcuts, and DevTools shortcuts. They do not exempt content from print rules or whole-page effects.

Each instance owns its handlers and styles. Destroying one leaves other instances active. Any guard can block an event in an overlapping scope. Avoid contradictory selection rules on overlapping targets, since visual selection styles follow the CSS cascade.

04 Lifecycle

guard.enable();                 // Apply saved configuration.
guard.disable('copy');          // Temporarily disable one feature.
guard.disable(['copy', 'print']);
guard.disable();                // Pause all features.
guard.enable();                 // Restore saved configuration.
guard.destroy();                // Release everything. Final and idempotent.

Disabling preserves the saved configuration and subscriptions. Explicit changes made with enable(options) update the saved configuration. After destroy(), enabling, disabling, or subscribing throws. Create a new instance to start again.

For components, create after mounting and disable during cleanup:

useEffect(() => {
  const guard = Guard.create({ target: articleRef.current });
  guard.enable({ copy: true, select: true, rightClick: true, savePage: true, print: true });
  return () => guard.disable();
}, []);

The global convenience methods Guard.enable(), Guard.disable(), and Guard.on() use a lazy document-wide instance. Prefer Guard.create() when different regions need different rules.

05 Events

const unsubscribe = guard.on('violation', event => {
  console.log(event.type);             // e.g. 'right_click'
  console.log(event.feature);          // e.g. 'rightClick'
  console.log(event.target);           // A DOM element.
  console.log(event.timestamp);        // Unix timestamp in milliseconds.
  console.log(event.originalEvent);    // Native event, or null.
  console.log(event.defaultPrevented); // Whether it was canceled.
});

unsubscribe();

Types include copy, select, right_click, save_page, print, console_open, and console_shortcut. Event records are frozen; DOM references remain live.

The optional onViolation(type, event) configuration callback can coexist with subscriptions. Each subscription has its own unsubscribe function. All listeners are invoked before the first thrown listener error is propagated.

06 Page-wide effects

A DOM scope is not a browser sandbox. Some operations affect the whole window:

  • Printing: the library hides only the target in print CSS. It cannot cancel the native print dialog. beforeprint notifications come from the window.
  • DevTools heuristic: dimensions are checked immediately, on resize, and every 500 ms. Sidebars and window layouts can trigger false positives. Detached tools do not provide the docked-panel size signal.
  • Hide: temporarily hides the scoped target, or the body for the document-wide instance. The original display style is restored when detection ends or the control is disabled.
  • Redirect: navigates the entire page to about:blank.
  • Shortcuts: interception only works when the page receives the event. Browser menus and browser-owned shortcuts may bypass it.

Frames, shadow roots, and browser chrome are not controlled as part of their parent’s DOM scope. Cross-boundary selections also have limits. Browser Guard is not DRM or access control, and cannot make delivered content private.

07 Anti-debugging

guard.enable({ antiDebug: true });
// Later, while JavaScript is running:
guard.disable('antiDebug');

This optional mode executes a static debugger statement every second. With a debugger attached and pauses enabled, it can pause execution even when DevTools is in a separate window. Without a debugger, the statement does nothing.

Debugger pauses affect the whole page.

While paused, the page cannot respond to its controls. To recover, disable breakpoints, resume execution, then disable this feature. Closing DevTools and reloading is another recovery path.

The mode is independent of console and consoleAction. It does not emit a violation because requesting a pause is not evidence that a pause happened. Users can bypass it by disabling debugger pauses. There is no infinite busy loop or dynamic code generation.

Framework examples

Install the package first, then create the controller after mounting and disable it during cleanup. Each example protects the whole page by default. The lifecycle hooks keep browser access out of server rendering. Add a target only if you want scoped protection.

React

useEffect creates the instance after mount and disables it on cleanup. Works with React Strict Mode; in Next.js, use a client component.

import { useEffect } from 'react';
import Guard from 'browser-guard';

export default function Article() {
  useEffect(() => {
    const guard = Guard.create();
    guard.enable({
      copy: true,
      select: true,
      rightClick: true,
      savePage: true,
      print: true,
      console: false,
      antiDebug: false,
      consoleAction: 'noop',
      onViolation: (type) => console.log('Guard:', type)
    });
    return () => guard.disable();
  }, []);

  return <article>Your content</article>;
}

Vue

Create the instance in onMounted; release it before the component unmounts.

<script setup>
import { onMounted, onBeforeUnmount } from 'vue';
import Guard from 'browser-guard';

let guard;

onMounted(() => {
  guard = Guard.create();
  guard.enable({
    copy: true,
    select: true,
    rightClick: true,
    savePage: true,
    print: true,
    console: false,
    antiDebug: false,
    consoleAction: 'noop',
    onViolation: (type) => console.log('Guard:', type)
  });
});
onBeforeUnmount(() => guard?.disable());
</script>

<template>
  <article>Your content</article>
</template>

Angular

afterNextRender runs in the browser. DestroyRef disables the controls when the component is destroyed.

import {
  Component, DestroyRef,
  afterNextRender, inject
} from '@angular/core';
import Guard from 'browser-guard';

@Component({
  selector: 'app-guarded-article',
  standalone: true,
  template: '<article>Your content</article>'
})
export class GuardedArticle {
  constructor() {
    const cleanup = inject(DestroyRef);

    afterNextRender(() => {
      const guard = Guard.create();
      guard.enable({
        copy: true,
        select: true,
        rightClick: true,
        savePage: true,
        print: true,
        console: false,
        antiDebug: false,
        consoleAction: 'noop',
        onViolation: (type) => console.log('Guard:', type)
      });
      cleanup.onDestroy(() => guard.disable());
    });
  }
}

08 TypeScript & package exports

The package includes matching declarations for ESM and CommonJS. Types cover feature names, options, active status, and violation events.

import Guard, { type ViolationEvent } from 'browser-guard';

const guard = Guard.create({ target: '#article' });
guard.on('violation', (event: ViolationEvent) => {
  console.log(event.feature);
});

Use one library entry point per application. Mixing the ESM and browser-script builds creates separate ownership registries. The editable source is src/guard-core.js; npm run build generates both distributable builds.
